# Браузерная проверка

Нужны работающий `docker compose up --build --wait`, Node 22.12+ и npm.
Зависимости теста зафиксированы в package-lock.json отдельно от frontend/.
Из этого каталога:

```sh
npm ci --ignore-scripts
npm test
```

Windows использует установленный Microsoft Edge в headless-режиме.
На Linux/macOS сначала установите тестовый Chromium:
`npx playwright install chromium`. При необходимости задайте PLAYWRIGHT_CHANNEL.
UI_BASE_URL по умолчанию http://127.0.0.1:8080.

Тест кликает три демо-профиля, проходит одобрение/встречное/отказ, принятие,
неверный код, подписание, выдачу, reload, историю и сброс. Проверяет реальные
POST/GET сервера, сумму, score и согласованную переплату, собирает JS-ошибки.
Скриншоты и отчёт находятся в игнорируемом artifacts/.
Тест создаёт синтетические заявки и в конце удаляет все демо-заявки через reset.
Исходники frontend/ тест не меняет; каждый профиль открывается в чистом контексте.

`node frontend-update.cjs` проверяет обновление cebb1d4: пересчёт подписи риска,
возврат исходных данных, кнопки назад во время проверки и после решения,
новый Idempotency-Key при повторной отправке и сохранение старых заявок в истории.

## БКИ и восстановление

При SIMULATE_BKI_FAILURE=true пересоздайте backend через compose, затем здесь:
`npm run test:bki:fail`. Проверяются NEEDS_RECHECK и кнопка retry; состояние
браузера сохраняется в artifacts/bki-storage.json.
Пока режим сбоя включён, повтор снова заканчивается NEEDS_RECHECK.

Верните SIMULATE_BKI_FAILURE=false, пересоздайте backend с тем же volume:
`docker compose up -d --force-recreate --wait backend` из корня.
Затем `npm run test:bki:recover` отсюда: проверяется восстановление той же заявки
после старта API и повторного открытия страницы. Данные сценария остаются до reset.

Лицензии инструментов сохранены в licenses/. Никакой браузерной авторизации
или пользовательского профиля Edge не используется, все тестовые данные синтетические.
