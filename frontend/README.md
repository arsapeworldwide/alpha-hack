# Фронтенд «Кредитный кабинет предпринимателя»

Веб-интерфейс заявки на кредит для малого бизнеса: компания → сумма и срок → проверка (ЕГРЮЛ, БКИ, скоринг) → решение (одобрение, встречное предложение, отказ) → подписание → выдача. Объясняет решение простым языком и показывает «запас прочности» ещё до отправки заявки.

## Запуск

### В Docker (как у жюри)

Из корня репозитория:

```bash
docker compose up --build
```

Откройте http://localhost:8080. По умолчанию фронтенд работает без бэкенда: данные хранятся в браузере (мок). Чтобы ходить в настоящий API, раскомментируйте сервис `backend` в `docker-compose.yml` и запустите:

```bash
VITE_USE_MOCK=false docker compose up --build
```

В PowerShell: `$env:VITE_USE_MOCK="false"; docker compose up --build`.

### Локально (для разработки)

Нужен Node 22 (см. `.nvmrc`).

```bash
cd frontend
npm ci
npm run dev        # http://localhost:5173
npm test           # 63 теста
npm run lint
npm run build
```

## Переменные окружения

Задаются при сборке (в Docker — через `docker compose`, локально — в `frontend/.env`, образец `.env.example`).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `VITE_USE_MOCK` | `true` | `true` — мок в браузере, `false` — запросы в `/api` |
| `VITE_API_BASE_URL` | `/api` | Адрес API. В Docker nginx проксирует `/api` на `backend:8000`; при `npm run dev` Vite проксирует на `localhost:8000` |
| `VITE_MOCK_BKI_FAILURE` | `false` | Мок имитирует сбой БКИ, чтобы показать «Нужна повторная проверка» |

## Сценарий проверки

1. Выберите «ООО «Альфа Ритейл»» → «Продолжить» → «Отправить заявку» → «Подписать договор онлайн» → код **1234** → кредит выдан.
2. «ИП Иванов» → в калькуляторе «Запас прочности» покажет, что 10 млн выходят за безопасный предел → «Отправить заявку» → встречное 2,5 млн ₽ → «Принять новые условия» → подписание.
3. «ООО «Вектор»» → отказ «Высокая долговая нагрузка», рекомендации, дата повторной подачи, лента переключается на советы.

Подробно, с ожидаемыми числами — `docs/TEST_SCENARIOS.md`. «Сбросить демо» — в тёмной полосе вверху страницы.

## Устройство

```
src/api/         контракт (types.ts), клиент (client.ts), мок (mockApi.ts, mock/), HTTP (httpApi.ts),
                 скоринг (scoring.ts), переходы статусов (stateMachine.ts), демо-данные (seed.ts, feedSeed.ts)
src/state/       reducer, сохранение в localStorage, опрос статуса заявки
src/features/    profile, calculator (+ запас прочности), application (карточка заявки),
                 pipeline, result, signing, history, feed
src/components/ui/  Button, Field, SliderField, Stepper, Modal, Badge, Term
src/lib/         аннуитет и округление, форматирование, даты
```

Контракт API — `docs/openapi.yaml`, состояния заявки — `docs/APPLICATION_STATES.md`, решения и допущения — `docs/REVIEW_NOTES.md`.

## Данные

Все данные синтетические; ИНН могут случайно совпасть с реальными. ЕГРЮЛ, БКИ, подписание и выдача — симуляции. Почта, SMS и внешние сервисы не используются; шрифт и иконки подключены из npm-пакетов, интернет во время работы не нужен.
