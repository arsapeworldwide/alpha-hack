# Умный кредитный кабинет предпринимателя

Фронтенд из origin/frontend и бэкенд объединены и опубликованы в main.
API адаптирован к контракту фронтенда. По выбору пользователя ручное редактирование
данных компании отключено: доступны демо-профили и поиск по ИНН в реестре.
По умолчанию интерфейс работает с настоящим сервером, а не браузерным мок-сервером.

Прототип для хакатона Альфа-Банка / Changellenge: заявка на кредит,
объяснимый скоринг, встречное предложение, подписание и выдача.

Реализованы БД, seed, бизнес-логика, API и асинхронный конвейер.
Docker-сборка, запуск, healthcheck и сохранение данных после перезапуска проверены.
Банковская роль реализована. Три исхода проверены кликами в браузере через nginx.
Добавлены вход, права директора/бухгалтера, изоляция компаний и рабочее место банка.
Демо-пульт БКИ переключает сбой без рестарта; решение сотрудника появляется у клиента автоматически.
Добавлены три продукта, согласие на БКИ, документы и ручное рассмотрение.
Банк предлагает свои условия; превышение платёжной способности требует обоснования.
Стек: Python 3.12, FastAPI, SQLAlchemy, SQLite / PostgreSQL 16, Alembic.
Код и Dockerfile находятся в backend/. Корневой requirements.txt ссылается
на backend/requirements.txt с точными версиями и хешами.

Все данные синтетические. ИНН могут случайно совпасть с реальными.
ЕГРЮЛ, БКИ, подписание и выдача реализованы как локальные симуляторы.
Код подписания — `1234`; почта, SMS и внешние сервисы в сценарии не используются.
Интернет потребуется для первоначальной загрузки образов и зависимостей;
в рантайме обращения в интернет не предусмотрены.

## Запуск в Docker

Нужны Docker с Linux-контейнерами и Docker Compose 2 или новее. Из корня репозитория:

```sh
docker compose up --build
```

Сайт: http://localhost:8080. Swagger: http://localhost:8080/api/docs
или http://localhost:8000/api/docs. Проверка: http://localhost:8080/api/health.
Seed загружается автоматически, `.env` не обязателен: используются безопасные
значения `.env.example`. SQLite хранится в именованном volume `backend_data`.
На экране входа выберите «Директор демо-группы» для трёх кредитных сценариев,
«Сотрудник банка» для очереди или «Бухгалтер Альфа Ритейл» для просмотра без подписи.
Демо-пароль: `demo-credit-2026`. Учётки привязаны к компаниям; чужая заявка возвращает 404.
Вход нужен и для прямых API-запросов; коллекция начинается с POST /api/auth/login.
Перезапуск и обычный `docker compose down` сохраняют заявки.
Запускаются frontend и backend, оба должны получить healthy. VITE_USE_MOCK=false
задаётся по умолчанию в compose; VITE-переменные применяются во время сборки.

Проверено на Docker Desktop 4.96.3 / Linux Engine 29.9.2 / Compose 5.6.1:
контейнер healthy, три сценария дают числа из SPEC, заявки сохраняются после
перезапуска, сбой БКИ восстанавливается после пересоздания контейнера, reset работает.
Скоринг также проверен в отдельном контейнере с `--network none`.
API и банковская роль дополнительно проверены через отдельный тестовый nginx;
команда его запуска — в [инструкции интеграции](docs/FRONTEND_INTEGRATION.md).
В реальном интерфейсе проверены одобрение, встречное предложение 2 500 000,
отказ, неверный код, подпись, выдача, перезагрузка, история и сброс.
Переплата согласована с фронтендом: округляется месячный платёж, затем считается
итог выплат. Для эталонов — 3 196 160 и 1 030 952 рублей, баллы — 97/46/8.
Подробная проверка и ограничения: [backend/README.md](backend/README.md).

Банковская роль: в Swagger Authorize введите demo-bank-token, затем откройте
GET /api/bank/applications. Для решения сотрудника используйте action/comment; counter также принимает amount/term_months
в POST /api/bank/applications/{id}/decision. Настройка — BANK_API_TOKEN через env.

Проверки: 227 тестов Python, 70 тестов фронтенда, ruff, ESLint и production build.
В tests/e2e находятся браузерные проверки Playwright; инструкции — в README этого каталога.
Изменения контракта и согласованное округление: [CONTRACT_CHANGES](docs/CONTRACT_CHANGES.md).


## Дополнительные сценарии

Перед отправкой нужно согласие на запрос в локальный симулятор БКИ. До него
реестр не раскрывает кредитную историю и текущие платежи. «Кредит на оборудование»
на 8 млн для «Северного» отправляется специалисту; исходные три эталона не меняются.
В банковской вкладке «Все заявки» можно запросить документы, затем директор
загружает синтетический PDF/PNG/JPEG до 10 МиБ и проверка повторяется.

PostgreSQL запускается вместо SQLite отдельной командой:

```sh
docker compose -f docker-compose.yml -f docker-compose.postgres.yml up --build --wait
```

Это отдельная БД, данные SQLite автоматически не переносятся. Обе схемы обновляет
Alembic при старте. Документы сохраняются вместе с БД в volume backend_data.
Перед показом: `docker compose exec -T backend python -m app.preflight`.

Реальные интервью ещё не проведены. Пять диалогов в CUSTDEV_SIMULATED.md —
вымышленные примеры для проверки гипотез, их нельзя выдавать за результаты исследования.
Постоянный сервер не предоставлен; временная публичная ссылка зависит от этого ПК.
