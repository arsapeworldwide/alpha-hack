# ADR 003: серверные сессии и принадлежность компаний

Статус: принято для P1.

Нужны выход с немедленным отзывом доступа, срок сессии и понятная изоляция
директора/бухгалтера/сотрудника банка. JWT не обязателен для одного API-процесса.
Выбран случайный Bearer-токен с 32 байтами энтропии; в БД хранится только SHA-256.
Пароль хешируется PBKDF2-HMAC-SHA256 со случайной солью и 600000 итерациями
через стандартную библиотеку. Новых зависимостей нет.

Токен лежит в sessionStorage вкладки, при выходе удаляется из БД и браузера.
Сессия переживает рестарт сервера, истёкшие токены не принимаются.
JS-хранилище требует защиты от XSS; для реального внедрения нужны HTTPS,
политика браузерной безопасности, промышленный IdP и управление пользователями.

Membership задаёт доступ к компании, а не к автору отдельной заявки:
директор и бухгалтер одной компании видят общую историю.
Права проверяются на сервере, чужой идентификатор даёт 404.
Синтетический директор группы имеет доступ к пяти компаниям специально для демо.
DEMO_MODE=false блокирует демо-пользователей и legacy банковский токен.

Лимитер неверных входов действует в памяти одного процесса. Для нескольких
реплик потребуется общий лимитер; прокси-заголовкам неизвестного клиента не доверяем.
За текущим nginx несколько посетителей могут иметь общий адрес прокси для этого
лимитера. Перед публичным внедрением нужно настроить доверенные адреса reverse proxy
и проверенную передачу клиентского IP; произвольному X-Forwarded-For доверять нельзя.
