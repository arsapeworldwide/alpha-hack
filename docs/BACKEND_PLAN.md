## Состояние и расхождения

Пользователь явно запросил подготовительный коммит и push в main;
это приоритетнее предложенной в брифе ветки backend.
Исходный SCORING_SPEC отличался от Приложения А только форматированием:
не хватало разделителя таблицы и двух пустых строк. По прямому запросу
пользователя файл заменён точным текстом приложения; числа не изменены.
Контракт фронтенда отсутствует. openapi.yaml и API_CONTRACT.md — черновики
бэкенда; сравнение с фронтендом пока невозможно.
Существующие app/, Dockerfile, requirements.txt и docker-compose.yml сохранены.
Настройка compose отложена до Фазы 3 вместе с Dockerfile бэкенда.

## Допущения для реализации

- Decimal для вычислений, half-up по SPEC; деньги в API — целые рубли.
- Одна реплика API и SQLite для демо; очередь и PostgreSQL — путь развития.
- +3 месяца означает календарные месяцы с ограничением последним днём месяца.
- Для неизвестной компании и повторной проверки точные ответы нужно
  согласовать с будущим контрактом фронтенда.
- Авторизация клиента в MVP не задана; синтетическая история общая для демо.
- Вопросы схем, ошибок, повтора идемпотентного запроса и полномочий
  банковского сотрудника конкретизируются перед реализацией API.

- Проверены сохранение SQLite после открытия нового engine, seed без дублей,
  каскадная очистка зависимых записей, внешние ключи и конфликт обновлений.
- API-контракт не менялся. Маршруты и журналирование запросов — Фаза 2.
