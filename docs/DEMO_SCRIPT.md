# Сценарий демонстрации

Запуск: `docker compose up --build --wait`, открыть http://localhost:8080.
Публичный туннель остаётся остановленным по просьбе пользователя.
Учётки и показатели синтетические; все карточки входа используют demo-credit-2026.

1. Войти как «Директор демо-группы». Сбросить демо, выбрать «Альфа Ритейл».
   Показать данные только для чтения и подписи источников.
2. Оставить 10 млн / 36 мес / оборотные средства. Отправить заявку.
   После этапов: 97 баллов, рейтинг A, ставка 19%, платёж 366 560 ₽.
   Переплата 3 196 160 ₽. Ввести неверный код, увидеть остаток 4; подписать 1234,
   дождаться выдачи. Перезагрузить страницу: заявка и результат сохранены.
3. Новая заявка, ИП Иванов с теми же условиями: 46 баллов, C,
   встречное 2 500 000 ₽, ставка 24%, платёж 98 082 ₽, переплата 1 030 952 ₽.
   Принять новые условия, подписать 1234, дождаться выдачи.
4. Новая заявка, «Вектор»: 8 баллов, D, отказ по нагрузке.
   Показать факторы, дату повторной подачи и три совета в начале ленты.
5. Для банковского сценария создать ещё одну заявку ИП Иванова и оставить
   встречное предложение непринятым. В другом окне/вкладке войти как
   «Сотрудник банка». Выбрать эту заявку, прочитать факторы и журнал,
   добавить комментарий и одобрить. В клиентском окне решение меняется само.
   Банк одобряет исходную сумму 10 млн под ставку SPEC: это ручное перекрытие
   capacity, не изменение модели. При score <45 одобрение недоступно.
6. Войти как «Бухгалтер Альфа Ритейл», открыть ещё не подписанную заявку
   Альфа Ритейл из истории: вместо подписи — «Подписать может руководитель».
   Чужие компании отсутствуют. Прямой запрос на подпись даёт 403.
7. В окне директора демо-группы нажать «Отключить БКИ», отправить новую заявку.
   Показать NEEDS_RECHECK. Нажать «Восстановить БКИ», затем «Повторить проверку»:
   та же заявка проходит в APPROVED без перезапуска сервера.
8. Показать банковский журнал с reviewer, выйти из кабинета: сессия отозвана.

Для банковского и бухгалтерского шага заранее не подписывать нужные заявки.
Сброс глобальный и удаляет все демо-заявки: не нажимать его посреди показа в другом окне.
Сессии изолированы по вкладкам (sessionStorage), заявки — по компаниям на сервере.

Браузерная автоматизация: tests/e2e/roles-ui.cjs и smoke-ui.cjs.
Резервные видео трёх исходов — docs/demo/; запись выполняется через Playwright
с RECORD_DEMO=1. Это фактические записи синтетического интерфейса, не интервью.
