## ЗАЯВКА И КОНВЕЙЕР
- Статусы: `DRAFT → SUBMITTED → CHECKING_EGRUL → CHECKING_BKI → SCORING → APPROVED | COUNTER_OFFER | REJECTED → OFFER_ACCEPTED → SIGNED → DISBURSED`. Плюс статус `NEEDS_RECHECK` («нужна повторная проверка») для случая недоступности внешнего сервиса.
- Допустимые переходы описаны в одном месте (`state_machine.py`). Недопустимый переход возвращает 409 с понятным сообщением. `APPROVED → sign` разрешён напрямую; `COUNTER_OFFER` требует сначала `accept-offer`; `SIGNED → DISBURSED` происходит автоматически через ~1 сек.
- Конвейер асинхронный: `POST /applications` возвращает 201 сразу со статусом `SUBMITTED`, дальше фоновая asyncio-задача проводит заявку по этапам (1 сек на этап, длительность из env `PIPELINE_STEP_SECONDS`, в тестах 0). Фронт опрашивает `GET /applications/{id}`. Статус сохраняется в БД на каждом этапе. Не используй Celery/Redis, это перебор для MVP; объясни в `docs/REVIEW_NOTES.md`, как масштабировать (очередь + воркеры).
- Устойчивость: при старте сервиса заявки, застрявшие в промежуточных статусах, дозапускаются. Каждый переход пишется в таблицу журнала (`application_events`: время, из статуса, в статус, актор: system/client/bank, детали).
- Ответ `GET /applications/{id}` содержит: статус, человекопонятное название статуса, массив этапов конвейера с состоянием и временем, данные компании, параметры заявки, результат решения (ставка, сумма, платёж, переплата), факторы скоринга (название, баллы, максимум, пояснение простым языком), причину отказа и рекомендации, дату повторной подачи.
- Симуляторы: ЕГРЮЛ и БКИ ищут компанию по ИНН в seed-данных; для неизвестного ИНН валидного формата (10 или 12 цифр) ЕГРЮЛ-симулятор возвращает «не найдено» (в мягкой форме), а невалидный формат даёт 422 с понятным текстом. Добавь переключаемый режим сбоя (env `SIMULATE_BKI_FAILURE=true`), чтобы показывать на демо корректную обработку недоступности внешнего сервиса: заявка уходит в понятный статус `NEEDS_RECHECK`, а не падает.

## ПРИЛОЖЕНИЕ А: текст docs/SCORING_SPEC.md (создай файл точной копией, если его нет)

```markdown
# SCORING_SPEC: единые правила решения (источник правды для фронта и бэка)

Все данные синтетические. Деньги: целые рубли. Округление: half-up.

## Входные данные
annual_revenue (₽/год), monthly_payments (текущие платежи по кредитам ₽/мес), credit_history (excellent|fair|poor), business_age_years, segment (retail|services|production), requested_amount, term_months (3–36), goal (working_capital|equipment|cash_gap).

## Скоринг 0–100 (сумма факторов, итог округляется)
1. История (макс 35): excellent 35, fair 20, poor 0.
2. Долговая нагрузка (макс 30): d = monthly_payments / (annual_revenue/12); баллы = 30 * clamp(1 − d/0.25, 0, 1).
3. Выручка (макс 20): ≥100 млн → 20; ≥50 млн → 16; ≥20 млн → 12; ≥10 млн → 8; иначе 4.
4. Возраст бизнеса (макс 10): ≥5 лет → 10; ≥3 → 7; ≥1 → 4; иначе 0.
5. Сумма к выручке (макс 5): q = requested_amount / annual_revenue; q ≤0,1 → 5; ≤0,3 → 3; ≤0,6 → 1; иначе 0.

## Ставка (годовая, %)
База по цели: working_capital 19, equipment 17, cash_gap 21.
Надбавка за риск: score ≥80 → 0; 60–79 → +2,5; 45–59 → +5.
Для cash_gap максимальный срок 12 мес.

## Платёжная способность
capacity = 0.25 * annual_revenue/12 − monthly_payments.
max_amount = приведённая стоимость capacity: capacity * (1 − (1+r)^−n) / r, где r = ставка/12/100, n = срок.
Платёж аннуитетный: P = S*r / (1 − (1+r)^−n). Переплата = P*n − S.

## Решение (проверять строго по порядку)
1. score < 45 → REJECTED.
2. capacity ≤ 0 → REJECTED.
3. max_amount ≥ requested_amount → APPROVED (сумма = запрошенная).
4. floor_100k(max_amount) ≥ 300 000 → COUNTER_OFFER на floor_100k(max_amount), срок и ставка те же.
5. Иначе → REJECTED.

Причина отказа (человеческим языком): если d > 0.25 или capacity ≤ 0 → «Высокая долговая нагрузка»; иначе если credit_history = poor → «Слабая кредитная история»; иначе если score < 45 → «Недостаточный уровень надёжности по итогам скоринга»; иначе → «Запрашиваемая сумма превышает платёжные возможности компании».
Отказ содержит 2–3 рекомендации и дату повторной подачи = сегодня + 3 месяца.
```
