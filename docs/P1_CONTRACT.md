# Вход, роли и демо-пульт

Расширение согласовано поручением пользователя реализовать рекомендованные пункты P1.
Правила SCORING_SPEC, статусы и финансовые эталоны остаются прежними.
Полный контракт экспортируется в openapi.yaml; исходный контракт фронтенда — в frontend/.

## Сессии

POST /api/auth/login принимает `{login,password}` и возвращает
`{access_token,token_type:"bearer",expires_in,user}`. Далее нужен
`Authorization: Bearer <access_token>`. GET /api/auth/me возвращает пользователя,
POST /api/auth/logout отзывает текущую сессию. Срок — SESSION_HOURS (по умолчанию 8 часов).
В БД хранится SHA-256 случайного токена; пароль — salted PBKDF2-HMAC-SHA256, 600000 итераций.
Новых зависимостей не добавлено. Токен в браузере хранится в sessionStorage.
Десять неверных входов с одного IP за минуту блокируют следующие попытки (429).
Лимитер действует внутри одного процесса и сбрасывается при рестарте; сессии остаются в БД.

Без сессии клиентские маршруты заявок возвращают 401. Чужая заявка — 404.
История фильтруется по memberships; участники одной компании видят общие заявки компании.
Idempotency-Key изолирован по пользователю. Старые записи заявок не удаляются и доступны
пользователям, которым принадлежит компания; схема applications не меняется.

Роли:

| Роль | Просмотр своей компании | Создание / принятие / подпись / retry | Банк |
|---|---|---|---|
| client_owner | Да | Да | 403 |
| client_accountant | Да | 403 | 403 |
| underwriter | Через банковские маршруты | 403 | Очередь, карточка, approve/reject |

Сотрудник банка использует ту же сессию. Добавлен GET /api/bank/applications/{id}.
Идентификатор сотрудника сохраняется в `events[].details.reviewer`.
Исходное автоматическое решение сохраняется в previous_decision события ручного решения.
Старый X-Bank-Token работает только при DEMO_MODE=true для совместимости коллекции.
Он обозначается в аудите как legacy-bank-token и не идентифицирует сотрудника.
При score <45 ручное одобрение по-прежнему запрещено (409).

## Демонстрационные учётки

GET /api/auth/demo-accounts возвращает карточки входа только при DEMO_MODE=true,
не возвращает паролей. Единый синтетический пароль задан в seed: `demo-credit-2026`.

| Логин | Доступ |
|---|---|
| director | Все пять seed-компаний; директор демо-группы для показа трёх исходов |
| retail-owner | Только Альфа Ритейл |
| services-owner | Только ИП Иванов |
| production-owner | Только Вектор |
| accountant | Бухгалтер Альфа Ритейл; только просмотр |
| underwriter | Все заявки через рабочее место банка |

DEMO_MODE=false выключает карточки, demo-profiles, reset и пульт, не создаёт демо-пользователей
и блокирует ранее созданные демо-учётки и их сессии. Для недемонстрационных пользователей
нужно отдельное администрирование: саморегистрации и промышленного IdP в этом прототипе нет.

## Демо-пульт

GET /api/demo/failures возвращает `{bki:"ok"|"down"}` для вошедшего пользователя.
POST с тем же телом доступен директору демо-группы и сотруднику банка, иначе 403.
Режим хранится в demo_failures и применяется к следующему запросу симулятора без рестарта.
Пока сохранённого режима нет, действует SIMULATE_BKI_FAILURE.
После восстановления БКИ клиент нажимает «Повторить проверку» у той же заявки.
POST /api/demo/reset доступен только этим же двум учёткам и только в DEMO_MODE;
он очищает заявки и возвращает БКИ в ok, оставляя учётки, сессии и seed.

## Интерфейс и совместимость

Новые 401/403 требуют входа перед прежними клиентскими запросами.
Добавлен код FORBIDDEN; остальные коды и структуры прежних ответов сохранены.
Клиентские страницы опрашивают сервер до DISBURSED, включая автоматические исходы,
поэтому ручное решение банка появляется без перезагрузки. После logout/смены пользователя
сохранённый UI-черновик очищается, серверные заявки не удаляются.
Черновики localStorage имеют отдельный ключ для каждого login; во вкладках одного
браузера разные учётки не подхватывают чужую компанию или открытый идентификатор заявки.
Бухгалтер видит текст «Подписать может руководитель» вместо кнопки подписи.
Промышленный MANUAL_REVIEW, второй голос и запрос документов в этот этап не входят.
