## Что сделано

**Клиентский путь (4 шага)**
- Компания: три демо-компании списком с меткой риска (по прогнозу решения), поиск по ИНН в синтетическом ЕГРЮЛ. Данные компании только для чтения — решение команды в `main` (ручная правка убрана).
- Сумма и срок: поле суммы со слайдером, срок, цель-переключатель (кассовый разрыв ≤ 12 мес).
- Изюминка «Запас прочности»: шкала доли месячной выручки (текущие платежи + новый платёж, линия 25%), прогноз «одобрят / одобрят меньше — до X / откажут: причина», кнопка «Взять X».
- Проверка: этапы ЕГРЮЛ → БКИ → скоринг двигает сервер, экран опрашивает `GET /applications/{id}` раз в 700 мс; сбой БКИ → «Повторить проверку».
- Решение: одобрено / встречное («Мы не можем выдать 10 млн ₽, но одобрили вам 2,5 млн ₽» с объяснением через запас прочности) / отказ (причина, советы, дата повторной подачи); «Что повлияло на решение» — 5 факторов.
- Подписание кодом 1234 (показан в окне, SMS запрещены), 5 попыток, затем выдача и «Кредит успешно выдан…».
- Навигация: карточка «Ваша заявка» справа вместо «Шаг N из 4»; «Назад» на шагах 2–4 («Назад к компании», «Отменить и изменить условия», «Изменить условия»); «Мои заявки»; «Сбросить демо» в демо-полосе; восстановление шага после перезагрузки.

**Умная лента**
- Разделы «Для всех», «Ритейл», «Услуги», «Производство»: у каждого свой цвет и иконки по темам; 5 статей на сегмент, 4 общих, 3 совета после отказа (идут первыми только после отказа).
- Тексты в одном файле для бэкенда `backend/app/db/feed_articles.json` и в моке `frontend/src/api/feedSeed.ts` — при правке менять оба.

**Инфраструктура и документы**
- `frontend/Dockerfile` (node:22-alpine → nginx:1.27-alpine), `frontend/nginx.conf` (SPA, gzip, заголовки безопасности, прокси `/api` → `backend:8000`).
- `docs/openapi.yaml`, `API_CONTRACT.md`, `APPLICATION_STATES.md`, `TEST_SCENARIOS.md`, `REVIEW_NOTES.md`, `frontend/README.md`, раздел фронта в `THIRD_PARTY_NOTICES.md`.

## Принятые решения и отступления от брифа

- Node 22 вместо 20 (Node 20 без поддержки с 04.2026, у Vitest 3 критические уязвимости).
- Дизайн: белая страница, серые плашки без теней, поля с заливкой, крупные заголовки; выбор — чёрным, красный только у главной кнопки и слайдера; без логотипа банка.
- Лента под шагом, а не боковой колонкой; справа карточка заявки.
- Переплата = округлённый платёж × срок − сумма (согласовано с бэкендом).

## Как продолжить в новой сессии

1. Прочитать `CONTEXT.md` в проекте и этот файл.
2. Папка на ПК: `C:\hack\alpha-hack\repo` (ветка `frontend`). Перед правками — `git pull origin main`, проверить, что локальные файлы совпадают с `main`.
3. Проверки фронтенда: `cd frontend && npm ci && npm test && npm run lint && npm run build`. Бэкенда: `cd backend && pip install -r requirements-dev.txt && pytest -q && ruff check .`.
4. Запуск всего проекта (фронтенд + бэкенд): `docker compose up --build`, сайт http://localhost:8080. Для разработки фронтенда без бэкенда: `cd frontend && npm run dev` (по умолчанию мок).
5. После правок: коммит и push в `frontend`, сообщить бэкендеру, что слить.
