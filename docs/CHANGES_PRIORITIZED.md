вход/выход, принадлежность компаний, бухгалтер, рабочее место банка, демо-пульт БКИ,

PostgreSQL и Alembic. Актуальный контракт — DEMO_FIXES_CONTRACT.md;

## Что изменилось относительно исходного списка

Список составлен для 96c20cf и частично устарел. Уже выполнены:

- Исключён ручной ввод показателей компании; реестр — источник данных сервера.
- Объединены новые лента, вкладка «Для всех», подсказки после отказа и остаток попыток подписи.
- Есть банковские approve/reject с токеном, аудитом и защитой от конкурентных изменений.
  Отдельного банковского экрана, назначения исполнителя и второго голоса пока нет.
- Есть снимок компании в заявке, журнал переходов, восстановление этапов после рестарта,
  идемпотентность, retry БКИ и ограничение попыток подписи. Новые таблицы не нужны для повторения этого.
- Есть документация, диаграммы, Swagger, лицензии, API-коллекция, Docker и browser e2e.
  Их нужно поддерживать при изменениях, а не создавать заново.
- Публичное демо ранее работало, сейчас остановлено по просьбе пользователя.
  Постоянный хостинг ещё не настроен.

Рекомендуемый порядок: стабильная интеграция → банковский экран → доступ и изоляция
компаний → удобный показ сбоя → короткие доказательства и документация.
Расширение кредитной политики и инфраструктуры идёт отдельными этапами.

## P1: следующий полезный объём

| Предложение из Changes.md | Решение | Польза и минимальный объём | Сложность |
|---|---|---|---|
| Экран банка | Оставить первым | Очередь, карточка, факторы, журнал и approve/reject поверх существующего API | Средняя |
| Авторизация и изоляция компаний | Оставить | Сначала клиент/банк и принадлежность заявок. Проверки 401, 403, чужая заявка 404 | Высокая |
| Четыре роли сразу | Сократить | Бухгалтер полезен для показа запрета подписи; старшая роль нужна только со вторым голосом | Высокая |
| JWT, bcrypt, конкретные библиотеки | Считать вариантом реализации | Сначала определить хранение сессии, сроки и роли; алгоритмы и пакеты выбирать после этого | Средняя |
| Лимит неудачных входов | Оставить вместе с login | Нужен, когда появится вход; сейчас маршрута login нет | Средняя |
| Демо-пульт отказов источников | Оставить в сокращённом виде | Сначала БКИ ok/down без рестарта, только в DEMO_MODE; сохранить retry и reset | Средняя |
| Источник рядом с фактом компании | Оставить | Пояснить, что реестр и БКИ — локальные симуляторы; клиент ничего не вводит | Низкая |
| Рейтинг A/B/C/D | Оставить как отображение | Производная от текущего score; не добавлять новую формулу риска | Низкая |
| Запасное видео, короткий сценарий демо | Оставить | Покрывает риск проблем с сетью и позволяет показать три исхода | Низкая |
| Обоснование MVP, краткие ADR | Оставить | Описать реальные решения и ограничения, не писать ADR для ещё не внедрённых технологий | Низкая |
| CustDev | Оставить отдельной работой команды | Провести настоящие интервью; зафиксировать выводы. Не генерировать цитаты респондентов | Зависит от команды |

В банковском экране сначала использовать существующий механизм доступа.
Полноценный вход добавлять согласованно на обеих сторонах; не удалять X-Bank-Token
до готовности замены и обновления проверок. Публичный сервис с реальными данными
потребует завершённой авторизации и изоляции до запуска.

## P2: полезно после P1, отдельными задачами

| Предложение | Решение и условие |
|---|---|
| Каталог кредитных продуктов | Сначала три текущие цели с действующими ставками и границами SPEC; отдельная таблица пока необязательна |
| Рекомендация продукта и срочность | После каталога; объяснение простыми правилами, без LLM |
| График платежей | Полезен после подписи; отдельно согласовать последний платёж и округление, чтобы график сходился с итогами |
| Подсказки «что изменить» | Считать на сервере по тем же правилам, не менять текущую оферту; не обещать одобрение |
| Согласие на запрос БКИ | Добавить с контрактом и проверкой сервера, если требуется выбранным сценарием; не выдавать демо-чекбокс за юридическую реализацию |
| ФНС, АБС, расчёт истории из просрочек | Это расширение модели данных и источников. Сначала описать входы и сохранить три эталона; не менять категории истории молча |
| Стоп-факторы | Отдельная согласованная политика: сейчас SPEC таких правил не содержит |
| MANUAL_REVIEW | После банковского экрана и доступа; рекомендацию системы хранить отдельно от решения сотрудника |
| Запрос документов / INFO_REQUESTED | После ручного рассмотрения. Нужны хранение, ограничения загрузки, права скачивания, восстановление и UI |
| Назначение исполнителя, журнал внешних проверок | Когда появляется ручная очередь и несколько сотрудников; текущую optimistic locking сохранить |
| Дополнительные персоны | Добавлять по одной под реализованную ветку, а не семь заранее |
| Более длинный срок / меньшая сумма как варианты | После серверной модели вариантов и точных правил accept-offer; текущий контракт не ломать |
| Отмена заявки | Отдельный согласованный endpoint; уход назад в текущем UI не отменяет старую заявку |
| Лента по новым статусам | Только после появления этих статусов; сейчас default/rejected достаточно |
| Метрики и банковский дашборд | Сначала несколько действительно используемых показателей, затем отдельный экран |
| История версий решений и policy_version | После повторного рассмотрения; сейчас есть снимок компании и аудит, это не полная история расчётов |

## P3: отложить для хакатонного MVP

| Предложение | Почему сейчас не приоритет |
|---|---|
| PostgreSQL 16 вместо SQLite по умолчанию | Текущий запуск и сохранение уже работают; дополнительный сервис увеличивает требования к запуску. Переход нужен при реальной конкурентной нагрузке |
| Alembic одновременно с полной схемой v2 | Нужен перед изменениями существующих таблиц; текущая интеграция меняет seed, а не схему. Не заменяет бэкап и проверку миграции |
| «Четыре глаза», подтверждение старшим | Нужны новые роли, незавершённое решение и аудит подтверждения. Слишком большой объём до готовности основного банковского экрана |
| SLA, EXPIRED, фоновые сроки 30 дней | Для короткого демо мало пользы; добавляют ещё один жизненный цикл и восстановление задач |
| Автоперевод к сотруднику после трёх retry | Сначала сама ручная очередь; число попыток и политика требуют согласования |
| Другой продукт как вариант оферты | Сначала каталог и сопоставимые правила ставок/сроков; иначе предложение трудно объяснить |
| Удалить весь браузерный мок и калькулятор | Мок полезен для автономных тестов фронтенда. Реальный режим уже включён по умолчанию; решение сервера окончательное. Дублирующую формулу постепенно заменить серверным preview |
| Брокер, outbox, несколько реплик | Описать путь развития; внедрять при реальной потребности. Сейчас поддерживается один процесс |
| Ollama / ИИ-помощник | Не решает текущие проблемы интеграции и требует ресурсов; опционально после DoD и отдельного подтверждения |

## Не принимать без отдельного согласования

- Новая ставка EXPRESS 22%, авто-лимиты 5/12 млн, налоговый порог 300 000,
  возраст 3 месяца, пороги просрочек и прочие числа v2 не определены действующим SPEC.
  В исходном Changes.md это предложения, не новые правила проекта.
- Передача только inn/product_code вместо company и замена банковского API —
  несовместимое изменение. Сначала CONTRACT_CHANGES, OpenAPI и план обновления двух сторон.
- Переход на ручную проверку вместо неизвестного ИНН изменит нынешний сценарий
  «нет в реестре». Нужны отдельные данные и источник для проверки новой компании.
- Точное число интервью, цитаты, оценки Reach/Impact и веса жюри нельзя подтвердить кодом.
  RICE без реальных данных создаёт видимость точности; пока достаточно MoSCoW и качественной оценки.
- Нельзя называть все семь персон готовыми или обещать семь разных веток,
  пока не реализованы сами статусы, источники и интерфейсы.

## Короткий список для следующего согласования

1. Банковский экран на существующем API.
2. Вход и доступ только к своим компаниям, затем сценарий бухгалтера.
3. Переключение сбоя БКИ из демо-пульта.
4. Источники данных и рейтинг рядом с уже имеющимися факторами.
5. Короткое демо-видео, реальные интервью и несколько ADR по фактически принятой архитектуре.
